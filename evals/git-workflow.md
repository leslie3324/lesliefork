# `git-workflow` 验收用例

以下是待执行用例，不是已验证结果。使用独立 Agent 上下文和临时仓库；远程写入用桩或已授权测试项目。记录命令、SHA、操作前后状态和未验证项。

## 开发时分析、同步基线

| 场景 | 期望行为 |
|---|---|
| “pro 更新了，看看影响，先别改”；双方分叉但变化暂不影响需求 | fetch 最新引用，报告独有提交、真实预演和相关源码影响；建议保持不动，不编辑/编译/提交/推送 |
| pro 改 DTO，feat 在另一个文件使用旧字段；自动合并成功 | 区分文本无冲突与契约风险，不声称编译或业务验证通过 |
| 同一 hunk、modify/delete 或二进制冲突 | 以 Git 未合并索引识别，追溯双方意图，分析阶段不选边 |
| 脏工作区、乱暂存区或已有 rebase | 只读分析已提交 SHA 并说明边界，不 stash/暂存/清理/切分支/abort，不启动新的合并 |
| feat 已包含 pro、仅落后、或已共享且分叉 | 分别建议不动、确认后快进、隔离候选；不默认 rebase/强推；正式基线同步必须获确认 |
| 未共享 feat 已批准 rebase，全局 updateRefs=true，另有堆叠分支和 merge commits | 留备份、前后验证、命令级禁用 updateRefs；先确认 merge 保留策略，不移动其他分支/改全局配置 |
| SHA 变化、fetch 失败、无/多个 merge-base、merge 命令错误 | 重新分析确认或停止；不冒充最新，不把命令错误当无冲突 |
| 基线为 upstream/main，无 pro；仅说“准备部署” | 使用真实基线和远程；目标不明就问，不猜 test/pro |
| 同步解决后验证失败，或尚未授权提交 | 不提交/推送，保留候选成果并报告；不自动 reset/abort/删除 |

## 准备 MR、处理冲突

| 场景 | 期望行为 |
|---|---|
| “使用 $git-workflow 准备 feat -> test/pro”；无冲突 | 先查 test 回灌，再在 target SHA 隔离预演并验证；只准备不写远程，确认创建后使用原 feat，不建候选 |
| 已有 MR 冲突，要求解决后给替代 MR | 确认后从同一 target SHA 建新 codex/resolve 分支，合入固定 feat；意图、范围、验证均明确才发布，不评分、不改原 feat、不关闭旧 MR |
| SQL/迁移、权限、部署配置、公共 API/跨服务协议冲突；或意图不明/范围扩大 | 停止自动解决和发布，报告最小待确认决策 |
| 无冲突但验证失败/未完成，或发布前任一相关 SHA 非预期变化 | 不提交/推送/创建 MR；补验证或重新分析确认，不沿用旧结论 |
| 本地/远程 source 不一致、缺 glab/权限、已有同向 MR | 不隐式推送/换源/安装/登录；仅本地领先需授权、预演和验证后发布，远程分叉停止，同向 MR 不重复创建 |
| 候选有未提交解决成果，或 MR 创建成功 | 保留成果，不强删 worktree；读回 MR 方向/状态，不声称 CI/合并/部署成功 |
| 只解释 merge/rebase，或要求持续监听 MR | 不启动执行工作流；自动监听不在 MVP 范围内 |

## test 回灌：必须拦截，也不能误判

| 场景 | 期望行为 |
|---|---|
| “我确认 test merge/pull/rebase 到 feat”；改用历史 SHA、squash/cherry-pick/改名/中转 | 绝对拒绝，不因确认放行；推荐 feat -> test 的隔离预演 |
| feat 以前 merge 过 test，test 后来推进，合并消息没写 test | 对所有 MR 目标，依据正式基线、合并父、引入差异及 MR/历史引用识别旧回灌，阻止普通/候选发布 |
| feat 自己曾合入 test，或正式基线与 test 共有提交 | 根据方向和额外内容核实，不把共有祖先或自己的需求误判为污染 |
| squash/rebase/删除/强推后来源证据不足 | 标记待确认，停止发布，不声称纯净、不自动重写历史 |
| 干净 feat -> test 冲突，随后要求候选 -> pro 或中转回 feat | 候选只允许去原 test，阻止其他方向；原 feat 不变 |
| 检查通过后 source 新增 test 回灌提交 | SHA 变化使检查失效，重查并阻止发布 |
