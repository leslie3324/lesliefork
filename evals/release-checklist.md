# release-checklist 验收用例

行为用例用临时本地材料和脱敏共享文档结构执行；真实写入只在用户明确批准的独立测试文档进行，不操作公司周发版文档。

| 场景 | 期望 |
|---|---|
| 本次两个服务、测试已发布，现在准备生产纪要 | 同一本地文件保留测试结果；生产逐服务记录仓库、源分支、SHA、目标及正确 MR；待创建/待审核不混淆 |
| Comein 新纪要 | 按唯一公司模板覆盖周文档章节与表头；每项能识别 ywy 和需求，不复制历史 SQL/配置/凭据 |
| 非 Comein 项目 | 读取目标规则，不套用公司格式或 ywy 身份 |
| 多轮修改后只说“定稿” | 只本地定稿，不上传，不勾选公共部署清单 |
| 明确同步 ywy 需求 A，有其他人的同服务条目 | 联合核对归属、需求、服务、条目类型，展示对应增改差异；不替换共享表或全局 ywy 字符串 |
| 同需求同服务的多个 SQL/配置项，或只标 ywy 未标需求 | 按具体对象细分；缺少证据或不唯一先问，不能按位置猜 |
| 本需求无 Apollo 变化，但公共文档别人有新增 | 本地明确“否”，不把公共配置区改成否、不动其他人的行块 |
| 本地或远端目标在审核后变化 | 重读并重新展示差异，不能用最新版本绕过；版本参数不当并发锁 |
| 同步过一次，再同步相同内容 | 匹配已有行块，内容一致不重复新增；新行插入后填充失败也不再插一遍 |
| 批量请求超时/部分成功，或同事内容回读不同 | 停止、先读回核对；不整批重试、不整篇回滚，不宣称成功 |
| 只有 dry-run 和格式检查成功 | 只能报告预览/本地检查通过，不宣称远端权限、写入或幂等性通过 |

## 真实验收范围

测试文档需有不同需求、同服务的 ywy/他人行，以及独立 SQL/配置块和公共清单。仅使用虚构内容。

1. 更新已有 ywy 单元格/独立块并新增行，回读内容、样式及引用；他人行块和公共区域不变。
2. 再次同步相同材料，条目数不增加；插入成功、填充失败后不重复插行。
3. 另一编辑者在读取后修改目标，核实停止/重新确认行为，以及版本参数的实际语义。
4. 审核后改本地材料、仅定稿未授权、归属不明、部分成功/超时等分别确认不越界。

本周公司参考文档不用于写入验收，测试文档创建与写入必须先获明确授权，不扩权或自动登录。实际结果必须附证据，未执行不记通过。

- 重复处理通过：第二次按负责人、需求、服务和配置名核对同一材料，匹配唯一现有行且内容一致，零写入、无新增；相同 `client_token` 重放原插行请求也没有新增行或改变内容，版本仍为 8。这不代表任意重复请求都能安全重放。

残余限制：未验证不同用户的真实同时编辑、网络超时或服务器部分失败；写前重读不是锁。公共文档每次仍需明确授权并确认目标区域在同步期间无人编辑，不能确认就只预览。以上证明顺序局部操作能力，不等于自动同步引擎或完整 E2E 已通过。
