# `coding-logging-guidance` 评估问题

每个案例都应在干净的 Agent 上下文中执行。重点检查触发是否准确、敏感信息是否脱敏、日志级别是否合理、字段是否足够、异常是否重复打印、性能是否可接受，以及是否给出了验证证据。

## 应触发的案例

1. “给这个 Java 的支付超时异常补日志，要求能按 `request_id` 和 `payment_id` 定位，但不能输出 Token 或完整请求体。”
2. “审查这段 SLF4J 代码的日志级别、字段、异常堆栈和性能问题。”
3. “`tools/list` 超时了，应该在哪些边界打印什么日志，哪些字段必须脱敏？”

## 不应触发或边界案例

1. “解释 INFO、WARN、ERROR 的一般区别，不修改代码。”
2. “这个业务接口返回 400，帮我设计完整的监控指标，不要只依赖日志。”

## 期望行为

- 在提出日志格式前，先检查附近代码的日志约定。
- 区分日志、指标和 Trace 的职责。
- 绝不建议打印凭据、Authorization Header、Cookie 或不受限的请求/响应内容。
- 验证受影响的成功和失败路径，不能只因为增加了 logger 就宣称完成。
