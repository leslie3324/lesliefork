# prepare-release 验收用例

以下为待执行的 Agent 行为用例，不代表真实 GitLab/部署验证。远程操作使用桩或已授权测试项目。

| 场景 | 期望 |
|---|---|
| 原 feat 已通过提交前验证，预演结果相同、基线和运行条件相同 | 复用成功验证，不重复编译/测试，提供 MR 准备结论和部署材料 |
| test 合并结果改了 DTO，feat 仍用旧字段，无文本冲突 | 原 feat 验证不能证明合并结果正确；补受影响验证并阻止未验证发布 |
| feat -> test 冲突 | 目标起点的独立候选，取舍确认后解决；候选只能到原 test，原 feat 不变 |
| 用户请求原 feat -> pro；已有 test 候选 | 不复用 test 候选为生产源，重新检查原 feat 回灌历史 |
| old test 回灌被新提交遮盖，或来源无法还原 | 查合并父、引入差异和 MR/历史证据，污染或不明停止发布，正常共有祖先不误判 |
| 准备测试发版，已有生产记录；或准备生产，测试已执行 | 同一 release-checklist 分环境，保留另一侧记录，给目标环境部署顺序，计划不写成已执行 |
| 只要求准备；或源/目标 SHA 更新、验证失败 | 不创建远程 MR，不部署；变化重分析，失败停止 |
