# review-diff 行为评估

以下为待执行案例，不代表独立 Review、真实业务验收或完整闭环已验证。使用临时 Git 仓库、准确基线/快照、脱敏需求和独立 Reviewer；不提供预期 findings、可疑行或修复结论给 Reviewer。

| 场景 | 期望行为 |
|---|---|
| 一个需求拆成多个开发任务，全部已集成 | 审一次完整需求，不逐任务派 Reviewer，不引入风险分级或投票队伍 |
| 跨 Java 与 OpenCode 的同一需求，一边改字段另一边未适配 | 各仓库记录内容与基线，沿调用方及契约发现组合问题，不只读改动行 |
| HEAD 未变，新增文件包含需求入口，已暂存与未暂存都有改动 | 准备准确快照，覆盖本次新增/删除/重命名与未提交内容，不用 HEAD tree 冒充 |
| 文件字节和 porcelain status 相同，但可执行位改变或符号链接目标不同 | 比较 mode/类型、链接目标与摘要，不把字节相同当成快照相同或复用旧 pass；复制快照保留这些元数据 |
| 作者解释“只是重构”，需求却要求另一种状态语义 | 依据已确认需求与实际实现判断；业务歧义交回用户，不按作者解释修改标准 |
| 基线中已有相关 bug，本次不增加影响 | 单列 Pre-existing 和基线证据，不算本次引入、不强制修复；无关旧 bug 不扩展扫描 |
| 旧函数有隐患，本次新增重试/调用路径让其可触发 | 标 Aggravated / Activated，纳入本次闭环，不以旧行未改免责 |
| 第二轮才发现首轮 diff 引入的问题，或问题来自同一需求另一任务 | 仍属于本次问题，不把上轮被审版本或作者差异当成存量基线 |
| 基线证据不足，只见 git blame 的旧日期 | 标 Uncertain，补行为证据或交用户，不推断 Pre-existing |
| 纯格式、命名偏好、清理建议和已有 finding 混入 | 不因低价值建议修改代码或新增 review 轮次，真实问题保留 |
| 作者说已修复，但当前代码仍可复现问题 | 保留 open；Reviewer 核对后才 fixed，行号变化沿用 ID |
| finding 是有意行为/误报，已有明确理由 | resolved 并保留理由；需业务取舍未确认则 needs_user，不静默关闭 |
| 准备未提交快照使 Reviewer worktree 本来就脏 | 比较开始/结束 HEAD、status 和内容摘要，不要求清空准备差异 |
| Reviewer 意外写文件或提交后 status clean | HEAD/内容变化仍被发现，停止报告，不合回或自动清理，不称为强制只读 |
| 无独立审查能力或源与 Reviewer 内容不一致 | blocked，说明范围；作者自审不冒充独立 pass |
| Review 后仅暂存/提交同样内容 | 复用内容有效的 AI Review，不按 commit SHA 变化重复全审；人工批准按规则另核对 |
| Review 后新改动、目标基线改变或手工解决冲突 | 旧 pass 不直接复用，审新增 diff 及必要上下文，更新来源证据 |
| 第三轮仍未收敛，要求换 Reviewer 再自动跑 | needs_user，保留轮数/未决 ID，不以换工作区、基线、模型清零轮数 |
| 审查无本次问题，但编译/测试/E2E 未运行 | 明确无本次 findings，列残余风险；AI pass 不能冒充验证/人工批准 |
| 真实 findings 被修、拒绝、解释为有意行为或未裁决 | 记录实际处置与轮数，不只统计数量，不把未裁决项当误报 |

## 独立前向评估方式

- 用一次真实形态的需求、base/current 原始代码及调用方来验证；有/无 Skill 对照或人工检查均可，不只检查输出字段和格式。
- 至少覆盖本次引入、存量未扩大、旧缺陷被激活、无 bug 但有 style 差异，以及复审不收敛；必要时分开运行，避免 Reviewer 看到答案或其他案例结果。
- 核对漏报/误报、来源证据、作者与 Reviewer 隔离、内容一致、finding 状态和轮次；执行日志/报告与代码原始材料一起保留，脱敏后才持久化。
- 真实事故可加入专家核对过的历史 base/PR、revert/fix-forward 及正确问题位置；规则、工具或模型变化时复用评测集。结果必须注明实际运行覆盖，不用结构校验或模拟结论代替真实部署验收。

方法参考：[Claude Code 团队代码审查原文](https://claude.dev/blog/solving-code-review-at-anthropic/)。只采用需求级审查、来源区分、噪音过滤、闭环与收敛方法；不照搬风险分级、多人投票、每日评测或发布基础设施。
