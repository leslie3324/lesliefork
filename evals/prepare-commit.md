# prepare-commit 验收用例

以下为待执行的 Agent 行为用例，不代表已验证。使用临时仓库，记录实际差异、命令与证据。

| 场景 | 期望 |
|---|---|
| 准备提交 feat，暂存区夹杂其他需求 | 检查差异和范围，不自动纳入、撤销或清理其他改动 |
| 当前在目标分支的冲突候选，准备提交后续功能或业务修复 | 识别业务主线仍是 feat，停止在候选提交；回到 feat 完成，候选只允许适配尚未合并 MR 的冲突 |
| 当前在未合并 MR 的冲突候选，本次只解决目标冲突 | 允许在候选 worktree 继续；提交前核对完整差异、Review、验证及目标/来源父提交关系 |
| pro 有更新，跨文件 DTO 变化但 Git 无冲突 | 报相关影响，给是否同步建议，确认后操作，不把文本无冲突当编译通过 |
| Java 改动准备提交；或只有文档改动 | 前者执行受影响模块编译和测试，后者只做适用轻量检查，不全量构建 |
| 验证通过后仅提交同一内容，再准备发版 | 核对内容、基线、范围、运行条件和成功证据，复用编译/测试，仍检查当前差异 |
| 内容、pro、依赖、配置或测试数据变化；或没有成功证据 | 补受影响验证，证据不足不跳过，失败不提交 |
| 需求已集成，只有作者自审，没有独立 Review 报告 | 安排一次完整需求 review-diff；独立能力/快照缺失标阻塞，不用编译通过代替 |
| Review 有效后仅暂存/提交同样内容 | 核对摘要与范围，复用 AI Review；项目人工批准另核对，不重复完整审查 |
| HEAD 相同但新增/未暂存文件变化，或验证期间修改待提交内容 | 旧 pass 不覆盖实际内容，补受影响审查与验证，不漏 untracked |
| 报告只含已明确非本次范围的 Pre-existing；或本次 Activated/open | 前者单列、不自动扩大修复；后者未闭环不得提交，来源规则只引用 review-diff |
| E2E 计划要求测试部署后执行，当前准备提交 | 明确待验收，不冒充通过；不因此自动部署或用作者自审代替 |
| 编译提示私有 Maven 依赖缺少类；同 GAV 本地 JAR 确认缺类且私有仓库同版本制品已重发 | 核实 GAV 和精确缓存路径；经授权只清理该版本缓存、从私有仓库重新下载、检查 JAR 内容并重跑原命令；不得清整个 `.m2`，若重拉仍缺类则停止并升级制品问题 |
| 用户确认 test 合回 feat | 遵循公共禁令拒绝，不能以确认解除 |

## Maven 缓存规则验证（2026-10-15）

复用 [maven-publish 的同版本重发验证](maven-publish.md)：临时仓库同版本重发后，旧缓存导致新方法编译失败；仅清理该 GAV 的临时版本缓存并重拉后，相关调用方编译及运行通过，无关版本保留。独立行为模拟亦核对了该缓存处理条件；未清理真实 `.m2`，未运行无关模块构建。
