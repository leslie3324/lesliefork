# 发版材料

1. 按文档治理在 `docs/<功能分支>/release-checklist.md` 维护本需求材料，先本地修改、供用户多轮审核。Comein 项目使用 [公司规则与模板](../../governance/comein/release-minutes.md)；其他项目按其规则，不套用公司格式。
2. 测试/生产分区，只改目标环境，保留另一侧和已有执行记录。开发分支按项目/服务逐项写仓库、源分支、SHA、目标和真实 MR/PR；未创建写待创建，已创建保持待审核，不批准、合并或关闭。
3. 只写本次发布事实、实际所需步骤和待办，不写 Agent 执行过程或重复 Git/验证规则。给出 SQL/配置、顺序和回退；未知写待确认，计划写待执行，不猜版本或结果。接口和测试明细只引用证据，敏感值只写受控来源。
4. 审核定稿不等于授权上传。明确同步到指定飞书文档后，使用 `lark-doc` / `lark-cli` 按目标项目同步规则执行（Comein 仅增改 ywy 条目）；先展示差异，归属不明或远端目标变化就停，不动他人内容和公共状态。
5. 返回本地路径、待确认事项；同步后回读目标及未改动内容，核对一致才报告成功。部分失败先读回，不整批重试或整篇回滚。
6. 只讨论给草案，明确生成/更新才写文件。本地忽略不妨碍维护，默认不纳入提交，不改 ignore、不强制添加。
