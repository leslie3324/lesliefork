# 发版材料

1. 按文档治理在 `docs/<功能分支>/release-checklist.md` 维护同一需求的材料；只取本需求差异、明确 SQL/配置及已确认结论，不混入其他需求。
2. 测试/生产分区记录，各自保留：开发分支、网关配置、定时任务、SQL、Apollo 配置、高频接口、数据中心协助、其他、发布结果。只更新本次目标，保留另一环境和已有执行记录。
3. 每项写对象、动作、前提及顺序；给出本次实际所需的部署步骤，可附准确 SQL/配置/命令。没有证据写待确认，确认不适用才写“无”；不猜版本、配置或执行结果。
4. 发布前记录计划和“待执行”，发布后只回写实际版本、时间、结果。接口及测试明细引用对应文档，不重复设计说明；敏感值只写受控来源。
5. 本地忽略不妨碍维护材料，默认不要求提交；不改 ignore、不强制添加。只有用户要求纳入提交且被阻塞才说明。只讨论给草案，明确生成/更新时写入并返回路径。
