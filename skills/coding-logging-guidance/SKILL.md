# 日志代码编写指导

修改日志前，先查看附近代码和项目约定，沿用现有 logger、MDC、结构化字段和脱敏方式。

以定位和排查用户问题为第一优先级：宁可补充有用的业务上下文，也不要只保留无法还原现场的泛化日志。

只要当前上下文中能够取得，就尽量完整记录用户信息，包括用户 ID、账号、昵称、租户、组织、角色、会话、设备、客户端版本、来源、地区、网络信息以及请求关联信息。只记录实际取得的字段，不编造字段；认证凭据和密钥类字段不作为普通用户信息记录。

## 必须遵守

- 每条日志都要对应一个有用的事件；优先覆盖请求入口、用户上下文、关键业务分支、状态变更、外部调用、超时、重试、回调、异常和最终结果，不要为普通方法进入/退出或高频正常路径增加噪声。
- `DEBUG` 用于诊断细节，`INFO` 用于重要生命周期，`WARN` 用于可恢复异常/降级/重试，`ERROR` 用于最终失败或需调查的系统故障。
- 优先记录 `event`、`request_id`/`trace_id`、完整可获得的用户字段、业务或资源 ID、关键请求/响应摘要、`result`、`error_code`、`duration_ms` 等稳定字段。
- 使用参数化日志；不要拼接字符串、序列化大对象，或在每层重复打印同一个异常堆栈。

## 输出与验证

编写或审查时说明：日志事件、级别、字段、脱敏方式和异常归属。完成后验证受影响的成功/失败路径、实际级别和字段，并明确报告尚未验证的部分。
