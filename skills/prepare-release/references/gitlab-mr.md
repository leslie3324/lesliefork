# MR 规则

- 确认源、目标、项目和已有 MR；本地/远程源不一致先说明，不偷偷换源或推送。
- 所有 MR 都查原 feat 的 test 回灌历史：看合并父、引入差异及相关 MR/历史来源，不只看分支名或最新 test HEAD；共有正式基线或 feat 自己的提交不算污染。已污染或来源不明就停止发布。
- 获取最新源/目标并固定 SHA，在独立 worktree 真实预演 `目标 <- feat`，用未合并索引判断冲突，不把目标合回原 feat；命令失败不能报无冲突。只清理自己的未编辑预演，不强删 worktree。
- 无冲突用原 feat；有冲突才从同一目标建立新的 `codex/resolve/...` 候选。先理解双方意图，取舍确认后解决；意图未明不自行选边。test 候选只能到原 test，不能回 feat 或提到 pro。
- 合并后的内容、基线或运行条件影响原验证时，按 prepare-commit 补受影响验证；不能用原 feat 的验证冒充候选已验证。发布前重新核对 SHA，变化就重新分析。
- 验证通过且提交/推送/创建 MR 在确认范围内才发布；只要求准备时不创建远程 MR。读回方向和状态，返回链接，不自动修改/关闭旧 MR 或合并，不丢弃未提交解决成果。
