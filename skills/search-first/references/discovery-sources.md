# 来源选择与检索边界

按问题选择来源，不把所有平台变成必查清单。先确定当前项目是否已有能力，再确定外部检索入口；用户要求广泛调研时覆盖多类相关来源，不以同一篇文章的转载充当独立证据。

| 需要找什么 | 发现入口 | 决策主源 |
| --- | --- | --- |
| 库、解析器、客户端、协议适配 | 对应生态注册表、GitHub 仓库/代码搜索、官方文档 | 包内容、目标版本源码、测试、支持矩阵、发行记录 |
| 可复用服务、CLI 或平台能力层 | 通用/语义搜索、官方产品入口、GitHub、真实使用讨论 | API/CLI 规格、源码、部署与权限要求、计费和退出方式 |
| Agent Skill 或工作流 | Skill 目录、相关仓库、社区使用记录 | 实际 `SKILL.md`、引用资源、脚本、运行时兼容和行为评估 |
| MCP Server | 官方注册表、相关生态目录、实现仓库 | 实际 schema/实现、传输/认证支持、部署要求；注册不证明适用或安全 |
| 架构或实现先例 | 问题语义搜索、GitHub 代码、设计文档、Issues/PR | 对应实现路径、设计前提、版本和已知限制 |

## 发现不是推荐

- 查询表达“问题 + 能力 + 环境/约束”，再用同义词和更上层抽象补查。例如跨平台访问问题搜“multi-platform agent internet access / authenticated social search / 跨平台信息获取”，不是搜 `search-first` 或 `tool-scout`。
- 搜索引擎、awesome 清单、Skill 目录和 stars 排名提供线索；社区讨论提供真实失败、使用场景和替代方案。都不能代替核心能力主源核验。
- 用户指定 X/Reddit 等平台时实际查询该平台。失败或没有已授权登录态就记录原因；网页 `site:x.com` 索引只能标作替代覆盖，不能称原生 X 搜索。广泛选型可先用语义搜索 + 实现主源 + 一个相关社区，不硬凑无关平台。
- 网络获取交给当前可用的 `agent-reach` 或其他已授权只读工具。工具退出码为 0 不代表拿到结果：检查正文是否为限流、登录页、错误或空列表。
- 每个决策相关来源记录 URL、查询词、查询日期及证据状态：`inspected`（读过主源）、`observed`（实际运行并有结果）、`snippet_only`（只见摘要）。同时保留精确版本/tag/commit；无法确认的填未知，不从页面更新时间猜发布日期。

## 什么时候停止

达到以下之一即可交付，不以填满候选数量为目标：

- 合格候选已足以比较关键取舍，继续搜索没有能指明的决策价值。
- 已覆盖相关主源入口，换过问题表述仍没有合格方案；给出范围化的“未发现”。
- 关键来源不可达、资格事实未知或达到用户预算；交付已知结果和覆盖缺口，必要时建议 `defer` 或后续定向补查。

增加搜索前说明它要解决哪项未知；不要用无限检索拖延结论，也不以次数证明“全网查遍”。
