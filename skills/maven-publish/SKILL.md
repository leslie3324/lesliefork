# Maven 制品发布

1. 读取目标仓库规则及本次模块 POM，核对源码、实际 GAV、制品类型、发布仓库和已有 Maven 接入；按 [发布与验证说明](references/maven.md) 检查版本是否已存在，不猜版本或把本机缓存当作远程制品。
2. 复用 [prepare-commit](../prepare-commit/SKILL.md) 的有效验证，仅补本次相关检查；复用前核对本次相关远程依赖摘要，同版本内容变化使受影响的旧验证失效。展示实际发布模块、GAV、仓库和命令，已有版本明确说明同版本重发风险，交用户确认。只要求检查就不发布，不强制改版本或顺带改调用方依赖。
3. 用项目已有 Maven 发布方式，仅发布批准的制品及必要 POM，不扩大到整个 reactor；允许经明确确认的同版本重发，远程状态不明或仓库拒绝重发时停止，不删除制品或修改仓库策略。部分失败先核对远程结果，不盲目整批重发。
4. 记录实际上传 JAR/POM 的摘要，从独立临时 Maven 缓存拉取远程包，对比摘要并检查本次相关类或内容，不能只看版本号。再核对调用方实际使用的包；旧缓存按 [prepare-commit](../prepare-commit/SKILL.md) 的规则处理，仅验证本次相关模块的必要编译、测试。内容未核实或只拉取成功不能报调用方可用。

返回发布、远程拉取和调用方验证的分别结果及证据，供发版流程引用。不部署服务，不删除整个 `.m2`，不自动修改仓库策略或扩大权限；缺少接入或授权就停止。凭据由已有 Maven settings 读取，不放在命令、日志或仓库；含凭据的访问只走已验证 HTTPS 或用户批准的安全通道。
