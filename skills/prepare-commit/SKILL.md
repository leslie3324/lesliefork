# 准备提交

1. 检查本次差异、暂存范围和未完成操作，不纳入无关改动；验证实际待提交内容，未暂存差异不能让验证对象与提交对象错位。
2. 获取最新 pro，分析提交关系、冲突及相关业务影响；给出是否同步及方式，确认后才更新 feat。
3. 按仓库规则，只执行本次需求相关模块的最小必要编译、相关测试和检查，不扩展到无关模块或全量验证；只改文档不跑业务构建。失败或结论未明就停止提交。
4. 返回能否提交及验证证据：仓库、已验证内容的 Git tree/文件摘要、基线 SHA、覆盖范围、命令、运行条件和结果；只要求检查不提交，明确要求提交且检查通过才按确认范围提交。

后续发布复用这份证据：相同内容、基线、范围和运行条件且验证成功，不重跑。仅暂存或提交相同内容不使验证失效；代码、依赖、配置、测试数据、环境或基线变化时，重做受影响检查。缺少可核对证据不能跳过，当前差异/暂存范围仍须检查。
